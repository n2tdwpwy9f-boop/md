# International Manpower Recruitment Platform

Candidate registration and talent-pool platform for an international manpower consultancy.
Built with Next.js 14 (App Router), Tailwind CSS and Supabase (Postgres, Auth, Storage).

- **Public site**: homepage, destination countries, job categories, 6-step candidate registration, success page with Candidate ID, privacy policy.
- **Admin dashboard** (`/admin`): overview statistics, searchable candidate database, full profiles, status tracking with history, internal notes, document downloads, CSV export, employer requirements with candidate matching and shortlists, countries and categories management, communication log, notification settings, admin users with roles.

---

## 1. Setup (about 15 minutes)

### Step 1: Create the Supabase project
1. Go to <https://supabase.com>, create a project and choose a region close to your candidates.
2. Open **SQL Editor** and run, in order:
   - `supabase/migrations/001_schema.sql`
   - `supabase/migrations/002_seed.sql`

   This creates all tables, Row Level Security policies, the private `candidate-documents` storage bucket, and the seed countries and categories.

### Step 2: Create your first admin
1. In Supabase go to **Authentication > Users > Add user**. Enter your email and a strong password and tick **Auto Confirm User**.
2. In **SQL Editor** run (with your email):

```sql
insert into public.admin_users (id, email, full_name, role)
select id, email, 'Your Name', 'super_admin' from auth.users where email = 'you@yourcompany.com';
```

Further admin users can be added from the dashboard under **Settings > Admin users**.

3. Recommended: in **Authentication > Sign In / Providers**, turn **off** "Allow new users to sign up". Admin accounts are created only by a super admin. (Even if sign-ups are left on, a signed-up user has no access to any data because they are not in `admin_users`.)

### Step 3: Configure environment variables
Copy `.env.example` to `.env.local` and fill in the values from **Project Settings > API**:

| Variable | Where to find it |
| --- | --- |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `anon` `public` key |
| `SUPABASE_SERVICE_ROLE_KEY` | `service_role` key. **Secret. Server only.** |
| `NEXT_PUBLIC_SITE_URL` | Your website address, e.g. `https://www.yourdomain.com` |
| `CRON_SECRET` | Any long random string (used by the data-retention job) |

Newer Supabase projects label these keys "publishable" and "secret"; use the publishable key as the anon key and the secret key as the service-role key.

### Step 4: Run locally
```bash
npm install
npm run dev
```
Website: <http://localhost:3000> · Admin: <http://localhost:3000/admin>

### Step 5: Deploy
The simplest host is **Vercel**: import the project, add the same environment variables, deploy. `vercel.json` already schedules the daily data-retention job. Any Node.js host that runs `npm run build && npm start` also works; in that case call `GET /api/cron/retention` daily with the header `Authorization: Bearer <CRON_SECRET>`.

## 2. Before going live

1. **Branding and contact details**: edit `src/config/site.ts` (company name, phone, WhatsApp, email, address, licence number). The name "Meridian Crest" is a placeholder.
2. **Hero image**: the hero uses a built-in illustration. To use a photograph, add `public/hero.jpg` and follow the note in `src/components/public/HeroArt.tsx`.
3. **Email**: emails are logged in the dashboard but not delivered until you configure a provider in `.env.local`:
   - **Resend**: set `RESEND_API_KEY` and `EMAIL_FROM` (a verified sender domain), or
   - **SMTP**: set `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASS` and `EMAIL_FROM`.

   Then open **Admin > Settings** to choose which notifications are sent and to which administrator addresses.
4. **Privacy policy**: `src/app/(public)/privacy-policy/page.tsx` is a practical template. Have it reviewed for the laws that apply to you (for example GDPR when recruiting for German employers, or your national data protection law).
5. **Spam protection**: the form has a honeypot field and a basic rate limit. For a busy public site, add a CAPTCHA (for example Cloudflare Turnstile) to `/api/register`.

## 3. How it works

### Registration
- The form validates each step in the browser and saves a draft in the browser session, so candidates can move back and forward (or refresh) without losing text they have entered. Selected files must be re-attached after a page refresh.
- On submit, the server (`/api/register`) validates everything again, inserts the candidate with the service role, and returns one-time signed upload URLs. Files are uploaded directly to the private bucket, which enforces the 5 MB limit and allowed file types (PDF, DOCX, JPG, PNG).
- The Candidate ID (for example `CND-26-001001`) is generated by the database.

### Roles
| Role | Access |
| --- | --- |
| Super Admin | Everything, including admin users, notification settings and permanent deletion |
| Recruiter | Candidates, documents, statuses, notes, requirements, shortlists, countries, categories |
| Viewer | Read-only. Cannot see or download documents |

### Candidate matching
Open an employer requirement and choose **Find matching candidates**. Each candidate is scored out of 100: job category 30, destination country 25, experience 20, qualification 10, skills 15. The scoring lives in the SQL function `match_candidates` and is easy to adjust.

### Verified vacancies
Nothing on the public site claims that vacancies are open. A requirement appears publicly only when a recruiter ticks **Publish as a verified vacancy** and its status is **Open**; the employer name is never shown.

### Data retention
Each profile is kept for 24 months from registration or the last status update (`retentionMonths` in `src/config/site.ts`). The daily job deletes expired profiles that are not in an active recruitment process, together with their files. A super admin can also delete a candidate permanently from the profile page (for erasure requests).

## 4. Security summary

- Row Level Security is enabled on every table. The public (anonymous) role can read only active countries, active categories and published vacancies. Candidate data is never reachable through the public API.
- Candidate inserts happen only on the server with the service-role key, which is never sent to the browser.
- Documents live in a private bucket. Staff download them through signed links that expire after 60 seconds.
- `/admin` pages require a signed-in session (middleware), and every query the dashboard makes is checked by RLS against the `admin_users` table and role.
- CSV exports are protected against spreadsheet formula injection.
- Security headers (`X-Frame-Options`, `nosniff`, `Referrer-Policy`) are set in `next.config.mjs`; admin pages are marked `noindex`.

Note: file type checks rely on the file extension, the declared content type and the bucket's allow-list. Files are never served publicly, but staff should still treat downloaded files with normal care (keep antivirus on).

## 5. Project structure

```
supabase/migrations/     Database schema, RLS policies, storage bucket, seed data
src/config/site.ts       Company name and contact details
src/lib/                 Field definitions, validation, email, Supabase clients
src/app/(public)/        Homepage, registration, success page, privacy policy
src/app/admin/           Login and dashboard pages
src/app/api/             Registration, admin actions, retention job
src/components/          Registration form and admin UI
```

To add or change a registration field, edit `src/lib/candidate-fields.ts` (form definition and server validation) and add the column in Supabase.
